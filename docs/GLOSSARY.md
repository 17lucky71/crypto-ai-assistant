# 과제 용어집

과제 문서에 나오는 단어를 **쉬운 설명 → 이 프로젝트에서 쓴 곳 → 질문받으면 하는 한 문장** 순서로 정리했다.

---

## 1. 서비스 구조

### 프론트엔드 / 백엔드
- **쉽게**: 프론트엔드는 사용자가 보는 화면(식당 홀), 백엔드는 보이지 않는 곳에서 데이터를 처리하는 서버(주방).
- **여기서**: `frontend/` 의 HTML·CSS·JS 가 화면, `backend/` 의 FastAPI 가 서버.
- **한 문장**: "화면은 Vercel 에, 데이터와 AI 처리는 Render 의 FastAPI 서버에 나눠 배포했습니다."

### API
- **쉽게**: 프로그램끼리 주고받는 "주문서 양식". 어떤 주소로 어떤 형식을 보내면 무엇이 돌아오는지 정한 약속.
- **여기서**: `/api/data`, `/api/chat` 같은 주소들.
- **한 문장**: "프론트는 API 로 백엔드에 요청만 보내고, 실제 계산과 저장은 백엔드가 합니다."

### 엔드포인트
- **쉽게**: API 의 주소 하나하나. "메뉴판의 메뉴 한 줄".
- **여기서**: 데이터 5개 + 대화 4개 + 채팅 1개 = 10개.
- **한 문장**: "과제가 요구한 엔드포인트를 모두 만들고, 대화 불러오기를 위해 `GET /api/conversations/{id}` 를 추가했습니다."

### HTTP 메서드 (GET / POST / PUT / DELETE)
- **쉽게**: 요청의 종류. GET 조회, POST 추가, PUT 수정, DELETE 삭제.
- **한 문장**: "같은 `/api/data` 주소라도 메서드에 따라 조회·추가가 나뉩니다."

### CRUD
- **쉽게**: Create(추가), Read(조회), Update(수정), Delete(삭제). 데이터를 다루는 기본 네 가지 동작.
- **여기서**: POST·GET·PUT·DELETE `/api/data`.
- **한 문장**: "화면에서 날짜·종가·메모를 추가, 수정, 삭제할 수 있고 바로 요약에 반영됩니다."

### 상태 코드
- **쉽게**: 요청 결과를 숫자로 알려 주는 것. 200 성공, 201 생성됨, 204 삭제 성공(내용 없음), 400 잘못된 요청, 404 없음, 409 충돌, 422 형식 오류, 500 서버 오류, 503 일시적으로 사용 불가.
- **한 문장**: "같은 날짜를 또 추가하면 409, 형식이 틀리면 422, AI 호출이 실패하면 503 을 돌려줍니다."

### JSON
- **쉽게**: 데이터를 주고받는 글자 형식. `{"date": "2026-10-07", "value": 165000000}` 처럼 이름과 값의 쌍.

## 2. 백엔드

### FastAPI
- **쉽게**: 파이썬으로 API 서버를 빠르게 만드는 도구(프레임워크). 문서(Swagger)를 자동으로 만들어 준다.
- **한 문장**: "파이썬으로 API 를 만들고, 입력 검증과 문서화를 자동으로 해 주기 때문에 FastAPI 를 썼습니다."

### Uvicorn
- **쉽게**: FastAPI 앱을 실제로 켜서 요청을 받게 하는 실행기. 앱이 "요리법"이면 Uvicorn 은 "가스레인지".
- **여기서**: `uvicorn main:app --reload` (main.py 파일의 app 을 실행, 코드 바뀌면 자동 재시작).

### 라우터 / 서비스 분리
- **쉽게**: 라우터는 "주문 받는 사람"(URL, 상태 코드), 서비스는 "요리하는 사람"(계산, 저장). 역할을 나눠 코드를 찾기 쉽고 재사용하기 좋게 한다.
- **여기서**: `app/routers/` 와 `app/services/`.
- **한 문장**: "라우터는 요청·응답만, 서비스는 로직만 맡게 나눠서, 채팅 API 가 요약 API 와 같은 요약 함수를 그대로 재사용할 수 있었습니다."

### Pydantic
- **쉽게**: 들어온 데이터가 정해진 형식에 맞는지 자동으로 검사하는 도구. "입구 검표원".
- **여기서**: `app/schemas.py`. 날짜 형식, 가격은 0보다 큼, 메모 200자 이하, 빈 메시지 금지.
- **한 문장**: "잘못된 값이 DB 에 들어가기 전에 Pydantic 이 422 로 막아서, 서비스 코드에서 일일이 검사하지 않아도 됩니다."

### 입력 검증 / 예외 처리
- **쉽게**: 검증은 "잘못된 값을 처음부터 막는 것", 예외 처리는 "문제가 생겼을 때 서버가 죽지 않고 알맞은 오류 메시지를 주는 것".
- **한 문장**: "없는 데이터는 404, 중복은 409, AI 실패는 503 으로 응답하고 프론트가 그 문구를 보여 줍니다."

### Swagger UI (`/docs`)
- **쉽게**: FastAPI 가 자동으로 만들어 주는 API 설명서 겸 테스트 화면. 브라우저에서 버튼을 눌러 API 를 직접 호출해 볼 수 있다.
- **한 문장**: "배포 주소 뒤에 `/docs` 를 붙이면 모든 API 를 확인하고 바로 실행해 볼 수 있습니다."

### 가상환경 (venv)
- **쉽게**: 프로젝트마다 따로 쓰는 파이썬 패키지 상자. 다른 프로젝트와 버전이 섞이지 않게 한다.
- **한 문장**: "venv 로 패키지를 프로젝트 안에 격리해, 다른 컴퓨터에서도 `requirements.txt` 로 똑같이 설치할 수 있습니다."

### requirements.txt
- **쉽게**: 필요한 패키지와 버전을 적은 목록. `pip install -r requirements.txt` 한 번으로 모두 설치.

## 3. 데이터베이스

### Firebase / Firestore
- **쉽게**: Firebase 는 구글의 앱 개발 플랫폼, Firestore 는 그 안의 클라우드 데이터베이스. 서버를 따로 관리하지 않아도 된다.
- **한 문장**: "데이터와 대화 기록을 Firestore 에 저장해, 서버를 껐다 켜도 남아 있습니다."

### 컬렉션 / 문서(document)
- **쉽게**: 컬렉션은 "폴더", 문서는 그 안의 "파일 한 장". 문서마다 자동 ID 가 붙는다.
- **여기서**: `data` 컬렉션(날짜별 종가), `conversations` 컬렉션(대화 하나 = 문서 하나, 안에 messages 배열).
- **한 문장**: "데이터와 대화를 두 컬렉션으로 나눴고, 대화는 메시지 목록을 문서 하나에 배열로 담았습니다."

### 서비스 계정 키
- **쉽게**: 서버가 Firestore 에 접근할 때 쓰는 "출입증" JSON 파일. 유출되면 누구나 DB 를 조작할 수 있다.
- **한 문장**: "키 파일은 GitHub 에 올리지 않고, 배포 서버에는 환경 변수로만 넣었습니다."

## 4. AI

### OpenAI API / GPT
- **쉽게**: ChatGPT 의 두뇌를 내 프로그램에서 호출하는 통로. 사용량만큼 요금이 나간다.
- **여기서**: `openai` 패키지 + Chat Completions 방식 그대로, `chat_service.py`. 주소만 Gemini 의 OpenAI 호환 주소(`gemini-2.5-flash`)로 바꿔 무료로 쓰고, 환경 변수 3개(`OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`)만 바꾸면 코드 수정 없이 GPT(`gpt-4o-mini`)로 돌아간다.

### 시스템 프롬프트
- **쉽게**: 대화 전에 AI 에게 몰래 주는 "역할과 규칙 안내문". 사용자는 보지 못한다.
- **여기서**: "당신은 데이터 분석 비서입니다. [사용자 데이터 요약] … 요약에 없는 건 추측하지 마세요."

### 컨텍스트 주입 ★ 가장 많이 물어봄
- **쉽게**: AI 는 내 데이터를 모르니, 질문할 때마다 **데이터 요약을 시스템 프롬프트에 붙여서** 함께 보내는 방법. 시험 볼 때 요약 노트를 같이 쥐여 주는 것과 같다.
- **흐름**: 질문 → 요약 계산 → 시스템 프롬프트에 삽입 → GPT 호출 → 답변 저장.
- **왜 전체가 아니라 요약인가**: 400일 원본을 다 보내면 토큰(비용)이 많이 들고 느리다. 평균·최고·최저·추세·월별 통계로 줄여 보내면 싸고 빠르면서도 대부분의 질문에 답할 수 있다.
- **한 문장**: "AI 를 다시 학습시키지 않고, 매 질문마다 최신 데이터 요약을 프롬프트에 넣어 주기 때문에 데이터를 수정하면 답변도 바로 바뀝니다."

### 토큰 / max_tokens
- **쉽게**: 토큰은 AI 가 글을 세는 단위(한국어 1~2글자 정도). 요금도 토큰 수로 계산된다. `max_tokens` 는 답변 길이 상한.
- **한 문장**: "비용을 막기 위해 답변 길이(`OPENAI_MAX_TOKENS`, 기본 500)와 이전 대화(최근 10개)를 제한했습니다. Gemini 2.5 는 '생각하는 과정'도 토큰에 포함돼 답이 잘려서 배포 환경에서는 1500 으로 올렸습니다."

### 할루시네이션
- **쉽게**: AI 가 모르는 것을 그럴듯하게 지어내는 현상.
- **한 문장**: "요약에 없는 내용은 '데이터에 없다'고 답하라는 규칙을 시스템 프롬프트에 넣어 지어내기를 줄였습니다."

### Function Calling (도구 호출) ★ 보너스
- **쉽게**: AI 에게 "필요하면 이 버튼들을 눌러도 돼"라고 버튼 목록(도구)을 주는 것. AI 는 직접 DB 를 못 만지지만, "이 도구를 이 값으로 실행해 줘"라고 요청하면 서버가 대신 실행해 결과를 돌려준다.
- **컨텍스트 주입과 차이**: 주입은 "미리 요약 노트를 쥐여 주기", 도구 호출은 "모르는 게 있으면 그때 찾아보게 하기".
- **여기서**: "3월 가격 어땠어?" → GPT 가 `get_price_range(3월 1일, 3월 31일)` 을 요청 → 서버가 계산 → GPT 가 답변. 화면에 🔧 표시.
- **한 문장**: "요약에 없는 특정 기간 질문은 GPT 가 스스로 기간 조회 도구를 불러 정확한 값을 가져와 답합니다."

### 도구 설명(description)과 호출 근거
- **쉽게**: GPT 는 각 도구에 적힌 설명을 읽고 어떤 도구가 질문에 맞는지 고른다. 그래서 설명을 "날짜가 정해진 질문에 쓴다"처럼 구체적으로 써야 엉뚱한 도구를 안 부른다.

### MCP (Model Context Protocol) ★ 보너스
- **쉽게**: AI 앱과 외부 도구를 연결하는 "공통 콘센트 규격". 한 번 MCP 서버로 만들어 두면 Claude 데스크톱 같은 여러 AI 앱이 같은 도구를 쓸 수 있다.
- **여기서**: `mcp_server/server.py` 가 우리 API 를 MCP 도구로 열고, Claude 데스크톱이 그걸 호출한다.
- **한 문장**: "같은 기능을 웹 화면뿐 아니라 Claude 데스크톱에서도 MCP 로 쓸 수 있게 연결했습니다."

### stdio
- **쉽게**: 프로그램끼리 표준 입력·출력(글자 주고받기)으로 대화하는 방식. Claude 데스크톱이 MCP 서버 프로그램을 직접 실행하고 이 통로로 요청을 보낸다.

## 5. 배포·보안

### 배포
- **쉽게**: 내 컴퓨터에서만 돌던 프로그램을 인터넷 서버에 올려 누구나 주소로 접속하게 만드는 것.

### Render
- **쉽게**: 백엔드(파이썬 서버)를 무료로 올릴 수 있는 호스팅 서비스. GitHub 와 연결하면 푸시할 때마다 자동 배포.

### 콜드 스타트 (슬립)
- **쉽게**: Render 무료 서버는 15분간 아무도 안 쓰면 잠든다. 다음 첫 요청 때 깨어나느라 30초~1분 걸리는 현상.
- **여기서**: 화면 위에 "서버 깨우는 중… N초" 표시, 4초마다 다시 확인 후 자동으로 데이터를 불러온다.
- **한 문장**: "무료 티어의 첫 요청 지연을 사용자가 고장으로 오해하지 않도록 안내 문구와 자동 재시도를 넣었습니다."

### Vercel
- **쉽게**: 프론트엔드(HTML 화면)를 무료로 올리는 서비스.
- **여기서**: 빌드할 때 환경 변수 `API_BASE_URL` 로 `config.js` 를 만들어 백엔드 주소를 넣는다.

### 환경 변수
- **쉽게**: 코드 밖에 따로 보관하는 설정값. 비밀번호 같은 키를 코드에 적지 않기 위해 쓴다. 로컬은 `.env` 파일, 배포 서버는 대시보드 설정 화면에 입력.
- **한 문장**: "키가 코드에 있으면 GitHub 에 그대로 노출되기 때문에 모두 환경 변수로 분리했습니다."

### .gitignore
- **쉽게**: GitHub 에 올리지 않을 파일 목록. `.env`, 키 파일, venv 등을 적어 둔다.

### CORS
- **쉽게**: 브라우저의 보안 규칙. 다른 주소(도메인)의 화면이 내 서버를 마음대로 호출하지 못하게 막는다. 서버가 "이 주소는 허락함"이라고 명단을 줘야 호출할 수 있다.
- **왜 필요한가**: 프론트는 `vercel.app`, 백엔드는 `onrender.com` 으로 주소가 달라서, 허용하지 않으면 브라우저가 요청을 차단한다.
- **한 문장**: "프론트와 백엔드 도메인이 달라서 CORS 설정이 필요했고, 아무나 호출하지 못하게 Vercel 주소만 허용했습니다."

## 6. 데이터 분석

### 시계열 데이터
- **쉽게**: 시간 순서대로 쌓인 데이터. 여기서는 날짜별 비트코인 종가.

### 종가
- **쉽게**: 그날 마지막 거래 가격. 업비트 일봉은 한국 시간 오전 9시 기준으로 하루를 나눈다.

### 요약 정보(통계)
- 평균, 최고·최저(날짜 포함), 기간 변화율, 30일 변화율, 월별 평균·최고·최저.

### 변동성
- **쉽게**: 가격이 하루에 얼마나 출렁이는지. 여기서는 "전날 대비 등락률(%)의 표준편차"로 계산.
- **한 문장**: "일간 변동성이 2.4%라면, 보통 하루에 ±2.4% 정도는 움직인다는 뜻입니다."

### 추세 판단 기준
- **쉽게**: 최근 30일 평균을 그 전 30일 평균과 비교. +3% 이상 상승, -3% 이하 하락, 그 사이 보합.
- **한 문장**: "하루하루 등락은 노이즈가 커서, 30일 평균끼리 비교해 추세를 정했습니다."

### 이동평균 (보너스)
- **쉽게**: 최근 N일 가격의 평균을 하루씩 밀면서 계산한 선. 들쭉날쭉한 가격을 부드럽게 만들어 큰 흐름을 보여 준다.
- **한 문장**: "그래프의 파란 점선이 30일 이동평균이고, 종가가 그 위에 있으면 최근 흐름이 평소보다 강하다는 뜻입니다."

### 상승일 비율 (보너스)
- **쉽게**: 전체 기간 중 전날보다 오른 날의 비율.
- **한 문장**: "상승일 비율이 50% 근처라 하루 단위로는 오르는 날과 내리는 날이 거의 반반입니다."

### 최대 낙폭, MDD (보너스)
- **쉽게**: 가장 높았던 가격(고점)에서 그 뒤 가장 많이 떨어진 비율. "최악의 경우 얼마나 떨어질 수 있었나"를 보여 준다.
- **한 문장**: "MDD -30%는, 고점에 산 사람이 한때 30%까지 손실을 봤다는 뜻입니다."

### 데이터 내보내기 (CSV / JSON) (보너스)
- **쉽게**: CSV 는 엑셀로 여는 표 파일, JSON 은 프로그램이 읽기 좋은 파일.
- **한 문장**: "저장된 데이터를 버튼 하나로 파일로 받아 엑셀에서 따로 분석할 수 있습니다."

### SVG (보너스)
- **쉽게**: 선과 도형을 좌표로 그리는 웹 그림 형식. 확대해도 깨지지 않는다.
- **한 문장**: "프레임워크·라이브러리 사용 금지 조건에 맞추려고 그래프를 SVG 로 직접 그렸습니다."

## 7. 자주 받는 질문과 답

| 질문 | 답 |
|---|---|
| 왜 만들었나요? | ChatGPT 는 내 데이터를 모르고 차트는 질문에 답하지 않아서, 실제 데이터를 근거로 대화하듯 답하는 비서를 만들었습니다. |
| 무엇이 이롭나요? | 어려운 차트 대신 쉬운 대화로, 지어낸 숫자 대신 실제 데이터로 흐름을 이해하게 돕습니다. 급락 때 과거에도 비슷한 날이 있었는지 바로 확인해 성급한 판단을 줄입니다. |
| AI 가 데이터를 어떻게 아나요? | 질문마다 데이터 요약을 시스템 프롬프트에 넣어 함께 보냅니다(컨텍스트 주입). |
| 데이터를 바꾸면? | 요약을 다시 계산하므로 다음 질문부터 바로 반영됩니다. |
| 키는 어떻게 관리했나요? | 환경 변수로만 관리하고 `.env` 와 키 파일은 `.gitignore` 로 제외했습니다. |
| 첫 접속이 왜 느리죠? | Render 무료 서버가 잠들어 있다가 깨어나는 시간이고, 화면에 안내와 자동 재시도를 넣었습니다. |
| 도구 호출은 왜 넣었나요? | 요약만으로는 "3월 가격" 같은 특정 기간을 정확히 모르기 때문에, 필요할 때 AI 가 직접 조회하게 했습니다. 요약으로 충분한 질문은 도구를 부르지 않아 비용도 아낍니다. |
| MCP 는 뭐가 좋나요? | 한 번 만든 기능을 웹뿐 아니라 Claude 데스크톱 같은 다른 AI 앱에서도 그대로 쓸 수 있습니다. |
| 투자에 써도 되나요? | 참고용입니다. 매매 신호는 항상 사유와 과거 적중률을 같이 보여 줘서, 믿을 만한지 사용자가 직접 판단하게 했습니다. 최종 판단과 책임은 본인에게 있습니다. |

## 매매 신호·알림 기능 용어

| 용어 | 쉬운 설명 | 한 줄 답변 |
|---|---|---|
| 이동평균(MA) | 최근 며칠 가격의 평균. 7일선은 단기, 30일선은 중기 흐름 | "7일 평균이 30일 평균 아래면 단기 하락 추세로 봤습니다." |
| RSI | 최근 14일 동안 오른 폭과 내린 폭의 비율(0~100). 70 이상 과열, 30 이하 과매도 | "너무 많이 오르거나 내렸는지 보는 지표입니다." |
| 모멘텀 | 최근 14일 동안 얼마나 올랐는지/내렸는지 | "움직이는 방향의 힘입니다." |
| 백테스트 | 같은 규칙을 과거 날짜에 적용해 실제로 맞았는지 채점하는 것 | "예측을 믿어도 되는지 숫자로 보여 주려고 넣었습니다." |
| 기준선(baseline) | 아무 규칙 없이 '오른다'(매수 비교용, 48.5%) 또는 '내린다'(매도 비교용, 51.5%)고만 했을 때의 적중률 | "규칙이 이것보다 높아야 의미가 있습니다. 매도 신호 50.4%는 '내린다' 51.5%와 비슷해서, 예측이 아니라 위험 신호로 씁니다." |
| 웹훅(Webhook) | 주소로 메시지를 POST 하면 디스코드 채널에 글이 올라가는 기능 | "디스코드 봇 없이 알림을 보내는 가장 간단한 방법입니다." |
| GitHub Actions | GitHub 이 정해진 시간에 명령을 대신 실행해 주는 기능 | "매일 아침 9시 5분에 알림 API 를 호출합니다." |
| 알림 토큰 | 알림 API 를 아무나 호출하지 못하게 하는 비밀 문자열 | "Render 와 GitHub Secret 에 같은 값을 넣어 둡니다." |
