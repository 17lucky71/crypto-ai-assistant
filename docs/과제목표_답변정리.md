# 과제 목표 6가지 — 이렇게 설명하면 됩니다

과제 문서의 "3. 과제 목표"에 나온 6가지를 평가자가 물었을 때 바로 답할 수 있게 정리했습니다.
각 항목은 **한 줄 답변 → 조금 더 설명 → 우리 코드에서 보여 줄 곳** 순서입니다.

---

## 1. 시계열 데이터를 분석해 요약을 만들고 서비스에서 쓰는 흐름

**한 줄 답변**
> "업비트 비트코인 일별 종가 400일을 Firestore 에 저장하고, 서버가 기간·개수·평균·최고·최저·추세를 계산한 요약을 만들어 AI 프롬프트와 화면에 함께 씁니다."

**조금 더**
- 흐름: 업비트 API → `seed_upbit.py` 로 정제(빠진 날짜·0 이하 값 확인) → Firestore `data` 컬렉션 → `build_summary()` 로 요약 → ① AI 시스템 프롬프트 ② 화면 요약 카드 ③ 위험 단계 계산
- 요약 항목: 기간, 개수, 최근 값, 평균, 최고·최저(날짜 포함), 30일 변화율, 변동성, 최대 낙폭, 이번 달 vs 월평균, 최고·최저 달, 추세(최근 30일 평균 vs 직전 30일, ±3% 기준 상승/하락/보합)
- 데이터가 바뀌면 요약 캐시를 지워 바로 다시 계산합니다.

**보여 줄 곳**: `backend/app/services/data_service.py` 의 `build_summary()`, Swagger 의 `GET /api/data/summary`

## 2. FastAPI 를 라우터/서비스로 나눈 기준

**한 줄 답변**
> "라우터는 '요청을 받고 응답 형식을 정하는 곳', 서비스는 '실제 계산과 저장을 하는 곳'으로 나눴습니다. 그래서 같은 계산을 API·AI 도구·MCP 가 함께 씁니다."

**조금 더**
- `routers/` : URL, HTTP 메서드, 상태 코드(404·409·503 등), 응답 모델만 담당
- `services/` : 요약 계산, CRUD, AI 호출, 위험 신호, 알림 등 핵심 로직
- `db.py` : Firestore 연결을 한곳에 모음 (키가 없으면 메모리 저장소로 대체)
- 장점: 예를 들어 기간 통계 함수 하나를 `/api/data/range`, AI 도구 `get_price_range`, MCP 도구가 **중복 없이** 함께 씁니다.

**보여 줄 곳**: `backend/app/routers/`, `backend/app/services/` 폴더 구조, `main.py` 의 `include_router`

## 3. Pydantic 으로 요청 검증을 한 이유와 방식

**한 줄 답변**
> "잘못된 값이 DB 나 AI 로 들어가기 전에 입구에서 막으려고 썼습니다. 모델에 규칙을 적어 두면 FastAPI 가 자동으로 검사하고 422 오류를 돌려줍니다."

**조금 더**
- `DataCreate`: `date` 는 날짜 형식, `value` 는 0보다 커야 함(`gt=0`), `memo` 는 200자 이하이고 앞뒤 공백 제거
- `ChatRequest`: 질문 1~1000자, 공백만 있는 질문 거부 → 빈 질문으로 AI 비용이 나가는 것을 막음
- 응답 모델(`DataSummary`, `ChatResponse`)도 정해 두어 Swagger 문서에 형식이 자동으로 나옵니다.

**보여 줄 곳**: `backend/app/schemas.py`, Swagger 에서 `value: -1` 로 POST 해 보면 422 오류

## 4. Firestore 에 저장하고 CRUD 로 다루는 방법

**한 줄 답변**
> "`firebase-admin` 으로 연결해 `data`·`conversations` 두 컬렉션에 문서로 저장하고, 추가·조회·수정·삭제를 API 5개로 만들었습니다."

**조금 더**
- `data/{자동ID}`: `date, value, memo, created_at, updated_at`
- `conversations/{자동ID}`: `title, messages[], created_at, updated_at` — 목록 조회는 messages 를 빼고 개수만, `GET /{id}` 에서 전체 messages 를 돌려줌 (과제의 (A) 방식)
- 같은 날짜를 두 번 넣으면 409, 없는 ID 를 고치면 404 로 막습니다.
- 보너스: 위험 알림 상태와 보낸 기록은 `alerts` 컬렉션에 저장

**보여 줄 곳**: `backend/app/db.py`, `services/data_service.py`, Firebase 콘솔의 컬렉션 화면

## 5. 컨텍스트 주입(데이터 요약을 시스템 프롬프트에 넣는 방식)의 원리

**한 줄 답변**
> "GPT 는 제 데이터를 모르니까, 질문할 때마다 서버가 최신 요약을 만들어 시스템 프롬프트 맨 앞에 넣어 줍니다. 그러면 GPT 가 그 숫자를 근거로 '내 상황에 맞는' 답을 합니다."

**조금 더**
- `POST /api/chat` 순서: ① 요약 조회 → ② 시스템 프롬프트에 삽입(기간·개수·주요 지표·트렌드 + 오늘의 위험 단계) → ③ GPT 호출 → ④ `conversations` 에 자동 저장
- 전체 400일 원본을 넣지 않고 **요약만** 넣는 이유: 토큰(비용)을 줄이고, GPT 가 핵심 숫자에 집중하게 하려고
- 요약으로 부족한 질문(예: "3월 가격은?")은 GPT 가 **도구(Function Calling)** 를 호출해 필요한 데이터만 더 가져옵니다.
- 규칙: 요약에 있는 숫자만 쓰고, 없으면 "저장된 데이터에는 없어요"라고 말하게 해서 지어내기를 막았습니다.

**시연 예시** (과제의 예시와 같은 형태)
- "이번 달 흐름 어때?" → "이번 달 평균은 ○○원으로 전체 월평균보다 ○% 낮은 수준이에요…"
- "가장 비쌌던 때는?" → "○월 ○일에 ○○원으로 가장 높았어요."

**보여 줄 곳**: `backend/app/services/chat_service.py` 의 `SYSTEM_TEMPLATE` 와 `chat()`

## 6. 배포에서 CORS·환경 변수·키 관리가 필요한 이유

**한 줄 답변**
> "프론트(Vercel)와 백엔드(Render) 주소가 달라서 CORS 로 허용한 주소만 API 를 부르게 했고, API 키와 Firebase 키는 GitHub 에 올라가면 도용되므로 코드가 아닌 환경 변수에만 넣었습니다."

**조금 더**
- **CORS**: 브라우저는 다른 주소의 API 호출을 기본으로 막습니다. `ALLOWED_ORIGINS` 에 Vercel 주소와 로컬 주소만 넣어 허용했습니다. 아무 사이트나 우리 API 를 쓰지 못하게 하는 효과도 있습니다.
- **환경 변수**: `OPENAI_API_KEY`, `FIREBASE_SERVICE_ACCOUNT_JSON`, `ALLOWED_ORIGINS`(Render), `API_BASE_URL`(Vercel). 코드는 그대로 두고 환경마다 값만 바꿉니다.
- **키 관리**: `.env`, `serviceAccountKey.json` 은 `.gitignore` 로 GitHub 에서 제외. 키가 노출되면 바로 삭제하고 새로 발급합니다(실제로 한 번 교체함).
- **비용 관리**: `OPENAI_MAX_TOKENS`, 이전 대화 10개만 전송, 도구 호출 최대 3회
- **무료 서버 대응**: Render 무료 서버가 잠들면 화면에 "서버를 깨우는 중" 안내와 자동 재시도

**보여 줄 곳**: `backend/main.py` 의 CORS 설정, `backend/app/config.py`, `.gitignore`, Render 환경 변수 화면(값은 가리고)

## 보너스 기능에 대한 예상 질문

| 질문 | 답변 |
|---|---|
| 왜 '코인 위험 알리미'인가요? | 코인 손실은 대부분 팔 타이밍을 놓쳐서 생깁니다. 그래서 "버는 것보다 지키는 것이 먼저다"를 철학으로, 위험할 때 먼저 알려 주는 비서로 만들었습니다. |
| 위험 단계는 어떻게 정하나요? | 추세(7일·30일 평균), RSI, 14일 모멘텀, 90일 고점 대비 하락, 30일 평균과의 거리 5가지가 투표해서 점수를 냅니다. −2 이하부터 '주의'(매도 신호)입니다. |
| 예측이 맞나요? | 장담하지 않습니다. 그래서 같은 규칙을 과거에 적용한 **적중률**과 **매도 신호 뒤 7일 평균 변화**를 화면에 그대로 공개합니다. 판단은 사용자가 합니다. |
| 디스코드 알림은 어떻게 오나요? | GitHub Actions 가 매일 09:05 에 서버를 깨우고 `/api/alerts/run` 을 부릅니다. 위험 단계가 '주의' 이상으로 오르면 이유와 함께 웹훅으로 보내고, 메시지를 누르면 대시보드 경보판으로 들어갑니다. |
| Function Calling 은 언제 쓰나요? | 요약만으로 답할 수 없을 때만 씁니다. 날짜가 정해진 질문은 `get_price_range`, "팔까?"는 `get_market_signals`+`get_recent_news`. 쓴 도구는 답변 아래 🔧 로 표시됩니다. |
| MCP 는 왜 했나요? | 같은 기능을 웹 채팅이 아닌 외부 AI(Claude 데스크톱)에서도 쓸 수 있는지 검증하려고, 도구들을 MCP 서버로도 열었습니다. |
